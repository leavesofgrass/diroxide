# Plugin protocol reference

This page is generated by `cargo xtask regen` from the methods module of `diroxide-plugins` (`protocol::methods`). Do not edit it by hand; change the module instead. The reasons behind each rule are in ADR-0006 and in the plan, section 5.8.

Protocol 1 has 51 requests and 15 notifications. Within protocol 1 only additions are made, and every method is optional: a host method the plugin did not declare in its manifest and confirm in `initialize` is never called, and a service the host did not offer in `host_capabilities` is never called by the plugin.

## Framing

- One JSON-RPC 2.0 message per line, UTF-8 without a byte order mark, in both directions. The host ends lines with `\n` and accepts `\r\n`.
- The longest line is 8 MiB by default; a plugin may ask for up to 64 MiB in its manifest. The reader enforces the limit while reading; a longer line is refused, and the next line is still read.
- A line that does not start with `{` or `[` after spaces is stray output: logged, counted and never answered. A line that starts with `{` and does not parse, or is not valid UTF-8, is answered with -32700 and a null id.
- Batches (JSON arrays) are refused with -32600.
- Standard error is free text for the plugin's log, never the screen.
- A plugin flushes after every message.

## Envelopes

- A request has `jsonrpc`, `id` (an integer or a string), `method` and optional `params`. A notification has no `id`. A response has the request's `id` and one of `result` or `error`, never both.
- `params` is always an object; absent means `{}`.
- Ids are unique per sender while outstanding; the host counts from 1.
- Unknown fields are ignored. An unknown request is answered -32601; an unknown notification is ignored.
- Names are `snake_case`; methods are `area/verb_noun`; names starting `rpc.` are never used.

## Error codes

`error.message` is one short sentence naming the cause only, meaning first. `error.data` carries `kind` (the name below) and optionally `place`, `hint`, `detail` and `retry_after_ms`. The host builds the owner's line, "Could not VERB OBJECT: CAUSE. NEXT STEP.", from them.

## Methods

Each method says who sends it, whether it is answered, what allows it, and whether alpha 2 serves it. A method marked "shape only" has its shape and fixtures fixed now, so it is decided once, and the host serves it when the feature that needs it arrives.

### Lifecycle

- `initialize`: host to plugin, request. Starts the conversation: the protocol major, both names and versions, and both capability lists. Allowed by: always. State: served.
- `initialized`: host to plugin, notification. Says the host accepted the initialize result. Allowed by: always. State: served.
- `shutdown`: host to plugin, request. Asks the plugin to stop; answered with null, after which only exit comes. Allowed by: always. State: served.
- `exit`: host to plugin, notification. Ends the plugin's process with code 0. Allowed by: always. State: served.

### Cancel, progress and the log

- `$/cancel_request`: either way, notification. Cancels an outstanding request by id; the request is still answered. Allowed by: always. State: served.
- `$/progress`: plugin to host, notification. Reports begin, report, end, a waiting state, or a partial batch of entries. Allowed by: a progress or partial token from the request. State: served.
- `log`: plugin to host, notification. Writes a line to the plugin's own log file, never to the screen. Allowed by: always. State: served.

### Commands and settings

- `command/run`: host to plugin, request. Runs one of the plugin's commands with the context. Allowed by: a [[command]] table. State: served.
- `settings/changed`: host to plugin, notification. Sends the whole settings object after the owner changes one. Allowed by: a [[setting]] table. State: served.

### Providers

- `provider/connect`: host to plugin, request. Signs in to an authority and returns its capabilities. Allowed by: a [[provider]] table. State: served.
- `provider/disconnect`: host to plugin, notification. Says the last lease on an authority ended. Allowed by: a [[provider]] table. State: served.
- `provider/list`: host to plugin, request. Lists a folder, in one answer or in partial batches. Allowed by: a [[provider]] table. State: served.
- `provider/stat`: host to plugin, request. Gives one entry's details. Allowed by: a [[provider]] table. State: served.
- `provider/read`: host to plugin, request. Reads a range of a file, inline or through the spool. Allowed by: a [[provider]] table. State: served.
- `provider/write_begin`: host to plugin, request. Starts a write session that commits or leaves nothing. Allowed by: the provider's methods list. State: served.
- `provider/write_chunk`: host to plugin, request. Sends one chunk of a write session. Allowed by: the provider's methods list. State: served.
- `provider/write_end`: host to plugin, request. Commits or abandons a write session. Allowed by: the provider's methods list. State: served.
- `provider/create_dir`: host to plugin, request. Makes a folder, with or without its parents. Allowed by: the provider's methods list. State: served.
- `provider/rename`: host to plugin, request. Renames or moves within the provider. Allowed by: the provider's methods list. State: served.
- `provider/create_link`: host to plugin, request. Makes a link at a place, symbolic or hard, to a target. Allowed by: the provider's methods list. State: served.
- `provider/remove`: host to plugin, request. Removes one entry; the job engine lists and confirms first. Allowed by: the provider's methods list. State: served.
- `provider/trash`: host to plugin, request. Moves one entry to the provider's own trash. Allowed by: the provider's methods list. State: served.
- `provider/set_attributes`: host to plugin, request. Changes attributes and times. Allowed by: the provider's methods list. State: served.
- `provider/copy_hint`: host to plugin, request. Says whether a server-side copy is possible, with no side effects. Allowed by: the provider's methods list. State: served.
- `provider/copy`: host to plugin, request. Copies on the server, with progress, cancellable. Allowed by: the provider's methods list. State: served.
- `provider/watch`: host to plugin, request. Starts watching a folder. Allowed by: the provider's methods list. State: served.
- `provider/unwatch`: host to plugin, request. Stops watching a folder. Allowed by: the provider's methods list. State: served.
- `provider/volumes`: host to plugin, request. Lists an authority's storages, free and total bytes; with a place, its one volume. Allowed by: the provider's methods list. State: served.
- `provider/places`: host to plugin, request. Lists the places the plugin offers, such as its sites, each row state first. Allowed by: the provider's methods list. State: served.
- `provider/changed`: plugin to host, notification. Reports created, changed, removed and renamed entries in a watched folder. Allowed by: a watch the host started. State: served.
- `provider/lost`: plugin to host, notification. Says a device was unplugged or a session ended, with the reason in words. Allowed by: a [[provider]] table. State: served.

### Previews and conversions

- `preview/render`: host to plugin, request. Makes a preview of a file. Allowed by: a [[previewer]] table. State: served.
- `convert/run`: host to plugin, request. Runs a conversion into a staged output. Allowed by: a [[converter]] table. State: served.

### Hooks

- `hook/before`: host to plugin, request. Lets the plugin continue or cancel a job before its confirmation. Allowed by: a [[hook]] table with a before event. State: served.
- `hook/after`: host to plugin, notification. Says a job ran, a folder was entered, or the selection changed. Allowed by: a [[hook]] table with an after event. State: served.

### Listers, columns, descriptions and completion

- `lister/open`: plugin to host, request. Shows rows that are not files in a panel, over its place, which returns when the list is left. Allowed by: a [[lister]] table. State: served.
- `lister/rows`: host to plugin, request. Asks for more rows of a lister, or a refresh. Allowed by: a [[lister]] table. State: served.
- `lister/closed`: host to plugin, notification. Says a lister's list left its panel: the owner left it, or a place replaced it. Allowed by: a [[lister]] table. State: served.
- `column/format`: host to plugin, request. Asks for a batch of a column's values, at most 500 places. Allowed by: a [[column]] table. State: shape only, served later.
- `column/changed`: plugin to host, notification. Says some of a column's values are stale. Allowed by: a [[column]] table. State: shape only, served later.
- `place/describe`: host to plugin, request. Asks for a short description of a place for the title line. Allowed by: a [[place_info]] table. State: served.
- `completion/query`: host to plugin, request. Asks for candidates for the text typed so far. Allowed by: a prompt whose completion source is the plugin. State: shape only, served later.

### Services the host offers

- `ui/announce`: plugin to host, notification. Says a sentence, cleaned, rate-limited and attributed to the plugin. Allowed by: always. State: served.
- `ui/ask`: plugin to host, request. Asks one question in a dialog; its message is one text or a list of lines. Allowed by: always. State: served.
- `ui/form`: plugin to host, request. Asks several labeled fields in one accessible dialog. Allowed by: always. State: served.
- `ui/show_text`: plugin to host, request. Shows a text document in the viewer. Allowed by: always. State: served.
- `ui/show_diff`: plugin to host, request. Compares two texts in the diff view. Allowed by: always. State: served.
- `panel/get`: plugin to host, request. Reads a panel's place, cursor, selection, sort and filter, and its plugin list or null. Allowed by: permissions.panel = read. State: served.
- `panel/set`: plugin to host, request. Changes a panel's place, cursor or marks, as ordinary commands; a place closes a plugin list. Allowed by: permissions.panel = write. State: served.
- `panel/changed`: host to plugin, notification. Tells a serve client that a panel's place, cursor, selection or plugin list changed. Allowed by: a serve client. State: served.
- `command/execute`: plugin to host, request. Runs a diroxide command by id. Allowed by: permissions.commands. State: served.
- `fs/list`: plugin to host, request. Lists a folder through the providers. Allowed by: permissions.fs = read. State: served.
- `fs/stat`: plugin to host, request. Gives one entry's details through the providers. Allowed by: permissions.fs = read. State: served.
- `fs/read`: plugin to host, request. Reads a range of a file, inline or through the spool. Allowed by: permissions.fs = read. State: served.
- `fs/write`: plugin to host, request. Replaces a whole file, inline or from the spool. Allowed by: permissions.fs = write. State: served.
- `fs/mkdir`: plugin to host, request. Makes folders as a job. Allowed by: permissions.fs = write. State: served.
- `fs/rename`: plugin to host, request. Renames entries as a job. Allowed by: permissions.fs = write. State: served.
- `fs/copy`: plugin to host, request. Copies entries as a job, with the engine's plan and undo. Allowed by: permissions.fs = write. State: served.
- `fs/move`: plugin to host, request. Moves entries as a job, with the engine's plan and undo. Allowed by: permissions.fs = write. State: served.
- `fs/delete`: plugin to host, request. Deletes entries as a job, to the trash by default, after the listing. Allowed by: permissions.fs = write. State: served.
- `fs/stage`: plugin to host, request. Hands out a staging path for an output the plugin creates. Allowed by: permissions.fs = write. State: shape only, served later.
- `fs/commit`: plugin to host, request. Moves a staged output into place as a job. Allowed by: permissions.fs = write. State: shape only, served later.
- `tools/run`: plugin to host, request. Runs an allowed tool with an argument list, never a shell line. Allowed by: permissions.tools. State: served.
- `tools/find`: plugin to host, request. Says whether a tool is found, where, and its version. Allowed by: always. State: served.
- `tools/launch`: plugin to host, request. Starts an allowed program detached and answers at once. Allowed by: permissions.launch. State: served.
- `tools/output`: host to plugin, notification. Sends a chunk of a streamed tool's output. Allowed by: a streamed tools/run. State: served.

## Additions of alpha 4

Additions within protocol 1, fixed by alpha 4's contract step so the lanes that serve them change no shape.

- `tools/run` takes `split` as `"lines"` (the default, at each line feed), `"nul"` (at each NUL) or `"cr"` (at each line feed and each carriage return, so a progress line a program rewrites in place, such as git's `clone --progress`, arrives as each rewrite; the empty record between a CR and its LF is dropped).
- A `[[provider]]` table takes `extensions`, the containers it claims inside archive places (disk images such as `.iso`, the 7z tool's formats such as `.rar`, raw images such as `.img`; never a format diroxide reads itself): a place such as `fedora.iso!EFI/` reaches the plugin, which opens each container once, and reads a container inside an archive through `fs/read`. It also takes `wants`, tools it uses when they are there and works without, which Settings names and nothing turns off.
- For `ui/form`, the app's side is `HostServices::form`, from a `Form` to a `FormAnswer` (`{"values": {"ID": VALUE}}` or `{"cancelled": true}`), fields of kind text, multiline, choice, checkbox, path and secret. Served since alpha 4: the app shows a list of setting rows, the default button's row first, then one row a field, its label first and its value after ("Message: empty", "Sign-off: off", "Password: hidden"); a multiline field answers its lines joined by line feeds, and Escape answers `{"cancelled": true}`.
- For `ui/show_diff`, the app's side is `HostServices::show_diff`, two documents in the compare screens. Served since alpha 4: the same screens as two files, in the same order (the verdict and counts, the direction, what was ignored, the files' facts, the change list, one change in full, the unified view, Swap), named by the two documents' titles, the view's title said last; a text with a NUL or many control characters is compared byte by byte; a document has no place, so the viewer does not open on it.
- For `place/describe`, the app calls `Host::describe_place` off the input thread for a folder a `[[place_info]]` matches; the answer's `text` is the title line's words. Called since alpha 4: when a panel lands in a folder whose scheme fits and whose marker is in it or a folder above it, the enabled plugins are asked in turn and the first words win; the title line says them after the panel, cut at 40 characters, the plugin's name last ("repo, left panel, main, no upstream, 2 changed here (Git), in D:\work"); the old title stays until the answer; the words are kept for the folder until it is listed again (a reload, a change the folder's watch sees, a job's end) or the plugin fails or is turned off; a plugin whose manifest declares no `[[place_info]]` is never asked.
- For `column/format`, file panels call `Host::plugin_columns` for the columns enabled plugins declare, keyed `PLUGIN.COLUMN`, and `Host::column_page` for a page of cells, "pending" where unanswered and "unavailable: plugin stopped" when the plugin cannot answer.
