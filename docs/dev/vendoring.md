# Vendored code

diroxide carries two folders of third-party Rust code under `third_party/`, copied from textweaver, the owner's other project, which maintains them: the GUI toolkit and AccessKit's Windows adapter, each with the patches textweaver carries against upstream. The GUI crate (`crates/diroxide-gui`) builds on them from the GUI alpha on (plan section 5, "GUI", and ADR-0007).

## What is here

- `third_party/xilem`: a trimmed copy of Linebender's Xilem repository at upstream revision 271a27a6d4a930f7878d404f9014e3c50a3a9b88 ("xilem: Expose imaging backends as features", Monday, September 14, 2026): the crates `masonry`, `masonry_core`, `masonry_winit`, `masonry_imaging`, `masonry_testing`, `tree_arena`, `include_doc_path`, `xilem`, `xilem_core` and `xilem_masonry`, and Parley 0.11.1 from crates.io. It is its own Cargo workspace. `third_party/xilem/TEXTWEAVER.md` lists every change textweaver made, and `textweaver.patch` holds them as one unified diff against upstream: AccessKit 0.25.1 and accesskit_winit 0.34.1, the accessible label on a text area, actions on nodes a widget adds itself, the tag released when a widget is removed, the tree update handed to AccessKit before the frame is rendered, and the rest.
- `third_party/fonts`: the font files textweaver bundles, copied whole on Monday, November 2, 2026: Atkinson Hyperlegible Next and Atkinson Hyperlegible Mono by the Braille Institute of America, and OpenDyslexic by Abbie Gonzalez, four styles each, under the SIL Open Font License 1.1 with each family's license file beside it (Lexend's folder holds only its license and notes; the font itself is not bundled). The GUI compiles in the two Atkinson families; the license obligations are in the folder's README.
- `third_party/accesskit_windows`: AccessKit's Windows adapter 0.35.1 from crates.io with one change, in `textweaver.patch`: the node's keyboard shortcut answered as UI Automation's AcceleratorKey property, so a screen reader says a button's key only when its own setting asks for it.

## The sync rule

- The copy is taken whole from textweaver's `main` with `git archive`, never edited by hand here. A change diroxide needs goes to textweaver first, where the patches live and are tested against its GUI, then the copy is refreshed and this page's revision line updated. The first copy was made on Monday, November 2, 2026, from textweaver's commit abd9585b, with every file's hash checked against textweaver's tree.
- **The one change diroxide carries:** `third_party/xilem/diroxide.patch`, beside `textweaver.patch`, removes `oxipng` from `masonry_testing` (the GUI alpha's contract step, Monday, November 2, 2026). oxipng's libdeflate back end compiles C, the only real C on the GUI's path, and only for the harness's screenshots; diroxide's copy writes a screenshot as the `image` crate encodes it. The patch is to be offered to textweaver; until textweaver carries it, a refresh of the copy applies it again after the copy (`git apply` in `third_party/xilem`), and the hash check covers every other file.
- The root workspace excludes `third_party/xilem` and `third_party/accesskit_windows` and depends on Masonry, `masonry_winit` (default features off) and `masonry_testing` by path, with `[patch.crates-io]` lines for `parley` and `accesskit_windows`, as textweaver's root manifest does. Only `diroxide-gui` depends on them, behind its `gui` feature, which `diro` turns on by default; `cargo xtask deps --check` holds all of this (the vendored folders excluded, every path a member's or a vendored folder's, patches from the vendored folders, the GUI crate their only user).
- AccessKit is pinned to textweaver's versions exactly (`accesskit` 0.25.1, `accesskit_winit` 0.34.1, `accesskit_consumer` 0.39.1): `accesskit_winit` 0.34.2 asks for `accesskit_windows` 0.35.2, and the patched 0.35.1 here would go unused. Moving to 0.25.2 and the adapter 0.35.2 (which fixes password disclosure, AccessKit 841) is a textweaver refresh first.
- The licenses are upstream's: Apache-2.0 for Xilem, Masonry and Parley, Apache-2.0 OR MIT for AccessKit, and the SIL Open Font License 1.1 for the fonts; `deny.toml` lists them, with the three zbus advisories (RUSTSEC-2026-0370 to 0372, unmaintained crates under AccessKit's Linux support) and the paste one (RUSTSEC-2024-0436, a build-time macro under wgpu's Metal backend) ignored with their reasons, as textweaver ignores them. `cargo xtask native --check` keeps the inventory of anything in the stack that compiles C: `wayland-backend` (only with its `log` feature, never turned on) and `android-activity` (Android only), both reasoned entries.
- Trace logs: textweaver's patch 13 makes Masonry write its full ("dense") trace log only into the folder `MASONRY_DENSE_LOG_DIR` names, never into the temporary folder on the system drive. The GUI also sets a quiet trace subscriber unless `RUST_LOG` or `MASONRY_DENSE_LOG_DIR` is set, so nothing is printed to the terminal `diro` was started from.
- Both folders stay out of the clean-room grep, the docs check and the format check, which cover diroxide's own code and pages.
