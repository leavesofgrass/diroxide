# The clean-room rule

diroxide reimplements the behavior of Worker, the orthodox file manager, without porting its code. Worker is licensed GPL-2.0-or-later; diroxide is Apache-2.0 OR MIT. A port of Worker's code would be a derivative work and could not carry diroxide's license, so the project keeps two roles apart. This page records the rule from the plan (section 3) and the list of specifications built from it.

## Two roles, never one agent

- **Research agents** read Worker's source and documentation and write specifications in their own words: what a feature does, its inputs, outputs, keys, edge cases and defaults, with file and line citations so the orchestrator can verify them. They never copy code, comments, configuration snippets or internal type names into a report.
- **Building agents** never read Worker's source. They build from the plan, the decision records, the research reports and public documentation.
- Every brief says which role it is. No brief is both.

## What may and may not enter the repository

- No Worker code, comments, configuration snippets or names of internal types.
- Default key bindings and user-facing behavior are not copyrightable and may match Worker's.
- Before a merge, the orchestrator searches the branch for Worker's internal names (the list is in plan section 3, and is kept out of every other file so the search has no false hits) and refuses a merge that contains one.
- The guard allows reads of the Worker source folder (research agents need them) and denies every write or delete there; building agents' briefs forbid reading it.

## The owner's own code

textweaver is GPL-3.0-or-later, but the owner holds its copyright, so the owner may release parts of it under Apache-2.0 OR MIT for diroxide (plan question 3, answered yes on Friday, October 9, 2026). Before any piece moves, the orchestrator confirms with the owner that no third party holds copyright in it. Phase 0 moved no textweaver code; it follows textweaver's designs (the list model, the keymap, the message rules) written fresh.

## Third-party notices

`THIRD-PARTY-NOTICES.md` will be generated by `cargo about` from the dependency tree, as in textweaver, once the first heavy dependencies arrive.

## The specifications

The research reports live in the planning repository's `research` folder. Each is written by a research agent and read by building agents.

- `worker-survey.md`: Worker's architecture, read-only, with citations (the planning session, Friday, October 9, 2026). Folded into plan section 2.
- `textweaver-method.md`: the textweaver method this project follows (the planning session).
- `worker-parity.md`: R1, the Worker parity inventory: every command, key, column, file-type rule, configuration block and viewer feature, with what diroxide keeps, changes or drops (Wave 0).
- `modern-features.md`: R2, the modern features inventory from other file managers (Wave 0, not yet written).
- `plugin-protocol.md`: R3, the review of the plugin protocol (Wave 0). Its wire conventions, error codes and shared shapes are folded into ADR-0006 and `diroxide-plugins`.
- `accessibility-stack.md`: R4, the accessibility stack check (Wave 0, not yet written).
